# حدود DevForge API أولًا

يوثق مركز **تحكم DevForge API** عقود المنصة عبر أصلها النشط والمسارات العامة أو المحمية. العقد لا يكشف مفاتيح API أو رموز الجلسات أو عناوين الخوادم الداخلية أو بيانات حسابات خارجية.

| النطاق | ما يعرضه المركز | ما لا يفعله |
| --- | --- | --- |
| API العامة | بوابة النقل، إشارة الصحة، وموجزات اعتمدت للنشر | لا يعرض سجلات المراجعة أو ملفات الزوار المعلقة أو مفاتيح التخزين. |
| أدوات المالك | وصف نطاق المصادقة لعقود مساحة العمل والبحث والمراجعة | لا يفتح المحتوى الخاص ولا يستدعي مزودًا خارجيًا عند فتح الصفحة. |
| مراجعة فصل API | سجل نية مراجعة داخل تفضيلات المالك | لا يغير الاستضافة أو المصادقة أو النطاق، ولا ينشئ اتصالًا أو مفتاحًا أو حسابًا. |

يظل عنوان الاستضافة النشط طبقة تشغيل حالية؛ أما عقد DevForge فيستخدم عنوان الأصل النشط مضافًا إليه `/api/trpc`. أي انتقال إلى استضافة مستقلة أو مزود API خارجي يحتاج نطاقًا يوافق عليه المالك، وخطة مصادقة وأسرار ومراجعة نشر منفصلة.

## تحقق الوصول

فُتح مسار `#/api-control` دون جلسة مالك في بيئة المعاينة. وصل المسار إلى بوابة تسجيل الدخول الخاصة بـ DevForge ولم يعرض بطاقات العقود أو إشارة الصحة أو زر مراجعة الفصل، ولم تُجرَ عملية اتصال أو كتابة.

أظهرت لقطة بيئة المعاينة اللاحقة الصفحة الرئيسية عند تمرير `/api-control` كمسار، لأن هذه الواجهة تستخدم توجيه الهاش ويُفقد الجزء `#/api-control` في مسار الالتقاط النسبي. لا يمثل ذلك فشلًا في مركز API؛ فتح الرابط الكامل مع الهاش هو التحقق الصحيح للمسار المحمي.
