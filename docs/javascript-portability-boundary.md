# جاهزية انتقال DevForge إلى محرك JavaScript

يعمل خادم DevForge الحالي بالفعل على **Node.js / TypeScript**، وهو مسار JavaScript منظم بعقود tRPC. لا يعني ذلك أن التشغيل مستقل حاليًا: ما زالت الاستضافة والمصادقة والتخزين وقاعدة البيانات خدمات مُدارة في البيئة الحالية.

| الطبقة | العقد الحالي الآمن | ما يلزم قبل نقلها | ما لا تفعله هذه الحزمة |
| --- | --- | --- | --- |
| واجهة الويب | React + TypeScript + تطبيق هاش | بناء وتشغيل JavaScript يختاره المالك | لا تنقل الواجهة تلقائيًا. |
| API | `/api/trpc` مشتق من أصل الموقع النشط | خادم Node.js، CORS، نطاق وTLS يملكها المالك | لا تكشف أسرارًا أو عنوانًا داخليًا. |
| المصادقة | جلسات وتحقق مالك داخل المزود الحالي | مزود هوية يختاره المالك وخطة ترحيل جلسات | لا تنقل حسابات أو رموز جلسات. |
| البيانات | جداول DevForge وملفات مخزنة بخدمة خاصة | نسخة احتياطية وخطة ترحيل ومراجعة صلاحيات | لا تصدر أو تحذف أو تنسخ بيانات. |
| الأسرار | مفاتيح خادم محمية في البيئة الحالية | خزينة أسرار في بيئة المالك | لا تعرض أو تصدر أو تعيد استخدام المفاتيح. |

## عقد بيئة JavaScript المقترح

بيئة مستقلة مستقبلًا تحتاج قيمًا يضبطها المالك، مثل عنوان التطبيق العام، المنفذ، عنوان قاعدة البيانات، سر جلسة جديد، إعداد مزود الهوية، وإعداد تخزين الملفات. تُحفظ القيم السرية في خزينة بيئة الخادم فقط، ولا تدخل الواجهة أو المستودع.

> **مراجعة الجاهزية ليست عملية نقل.** تسجيلها في DevForge يحفظ نية المالك للمراجعة فقط، ولا يغير الاستضافة الحالية أو DNS أو GitHub أو OAuth أو التخزين أو قاعدة البيانات.

## طبقة إدارة الذكاء الاختيارية

يمكن لطبقة الذكاء في DevForge أن تساعد في التخطيط والتشخيص وإعداد مسودات مراجعة عند طلب المالك، لكنها ليست شرطًا لتشغيل الواجهة أو API أو قاعدة البيانات أو نظام الصلاحيات. تحتفظ الخدمات المبنية بـ JavaScript بعقودها وحالاتها دون تشغيل نموذج. وعند اختيار مزود ذكاء بديل مستقبلًا، يمر ذلك بإعداد مالك مستقل ومراجعة بيانات وأسرار؛ لا تقوم المنصة بالتبديل أو النقل تلقائيًا.
