# حدود استمرارية DevForge

## المبدأ التشغيلي

تشغيل الموقع المنشور منفصل عن جلسة المحادثة. تعرض صفحة `#/continuity` إشارة صحة محدودة من خادم DevForge فقط، ولا تصل إلى بيانات الزوار أو حسابات المالك أو أي حساب خارجي. لا يعني الفحص نجاح كل مزود خارجي أو ضمان إتاحة كاملة.

| المسار | ما يفعله | ما لا يفعله |
|---|---|---|
| فحص الصحة | يقرأ نتيجة استجابة محدودة من خادم DevForge. | لا يعيد تشغيل خدمة ولا يعدل نشرًا أو بنية تحتية. |
| محطة JavaScript | تشخّص تجربة محلية معزولة وتعرض اقتراحًا للمراجعة. | لا تصل إلى الشبكة أو الأسرار أو ملفات المنصة ولا تطبق إصلاحًا تلقائيًا. |
| طلب مراجعة المراقبة | يسجل رغبة المالك في مراجعة نطاق مزود موثق. | لا ينشئ مراقبًا أو حسابًا أو مفتاحًا أو تنبيهًا أو يرسل بيانات. |

## مراجع خدمات المراقبة

| الخدمة | الاستعمال المحتمل | شرط التفعيل |
|---|---|---|
| UptimeRobot | مراقبة رابط موقع أو API يحدده المالك. | إعداد مستقل ومراجعة الحصة والخصوصية في حساب المالك. [1] |
| Better Stack Uptime | مراقبات وحوادث وصفحات حالة. | إعداد مستقل في حساب المالك. [2] |
| Healthchecks.io | متابعة وصول إشارات نجاح للوظائف الدورية. | التعامل مع رابط ping ومفتاح المشروع كمادة حساسة وعدم إدخالهما في DevForge. [3] |
| Sentry | مراقبة الأخطاء والأداء بعد اختيار نطاق البيانات. | تفويض مستقل وتقييم إعدادات جمع البيانات والتنبيه. [4] |

## تحقق الوصول

في 27 أغسطس 2026، فُتح مسار `#/continuity` في بيئة المعاينة دون جلسة مالك. بعد اكتمال التحميل القصير ظهرت بوابة تسجيل الدخول فقط، ولم تظهر إشارة الصحة أو خدمات المراقبة للزائر غير المسجل.
